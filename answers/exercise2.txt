into the container:

---------------------------------------------------------

The following is the full shell session transcript. Everything from the
"root@51a4f189bed6:/#" prompt onwards was typed and executed *inside* the

root@51a4f189bed6:/# ls /usr/src

root@51a4f189bed6:/usr/src/app# cat /usr/src/app/index.js

3. Verification after exiting the container
--------------------------------------------

The container exited cleanly with status 0 and both the directory and the file
persisted in the container's filesystem after `exit`:

$ docker container ls -a --filter name=fsopen-exercise2 --format '{{.Names}} | {{.Image}} | {{.Status}} | {{.Command}}'
fsopen-exercise2 | ubuntu | Exited (0) | "bash"

$ docker run --rm fsopen-ex2-verify ls -la /usr/src/app
total 12
drwxr-xr-x 2 root root 4096 Oct 21 06:28 .
drwxr-xr-x 1 root root 4096 Oct 21 06:27 ..
-rw-r--r-- 1 root root   49 Oct 21 06:28 index.js

$ docker run --rm fsopen-ex2-verify cat /usr/src/app/index.js
console.log('Hello from /usr/src/app/index.js');


4. What the exercise demonstrates
---------------------------------

* `docker container run -it ubuntu bash` creates a *container* (runtime
  instance) from the *image* ubuntu:latest, and `-it` gives the container an
  interactive TTY so that bash is attached to the terminal.
* The `root@<id>:/path#` prompt shows that the shell is running *inside* the
  container, not on the host. The prompt's current directory changes with
  `cd`, which proves the commands act on the container's filesystem.
* `mkdir /usr/src/app` and the redirection `> /usr/src/app/index.js` create
  the directory and the file inside the container's writable layer. The file
  survives `exit` because the container is only stopped, not deleted.
* `exit` terminates the bash process, the container stops, and Docker keeps
  the filesystem changes until the container is removed with
  `docker container rm`.

Note: the container was created with `--name fsopen-exercise2` only so that
it could be inspected afterwards; the command itself is exactly the one
suggested by the hello-world output.
